# Sales-channel ingest (D26)

Posting rules: `docs/CHANNEL_POSTING_MAP.md` (approved 2026-09-30). Code:
`apps/ledger/src/channel/`, CLI in `channel_cli.rs`, tests in
`apps/ledger/tests/channel.rs`, fixtures (synthetic) generated by
`tools/gen-channel-fixtures.py`.

## Commands

```
ledger import shopify-payouts --db D --company C --payouts P.csv --transactions T.csv [--orders O.csv --lines L.csv [--refunds R.csv]]
ledger import shopify-orders  --db D --company C --orders O.csv --lines L.csv [--refunds R.csv]
ledger import amazon-unified  --db D --company C --file F.csv
ledger import amazon-settlement-v2 --db D --company C --file F.txt
ledger import walmart-recon --db D --company C --file RECON.csv [--as-of DATE]
ledger import etsy --db D --company C --file STATEMENT.csv [--file ...]   # all months in ONE call
ledger report channel-sales --from --to [--by family|sku] [--channel c] [--format csv|json|text]
ledger report channel-recon --from --to [--format csv|json|text]
ledger sku-map list|unmapped|set --db D --company C [--channel c --sku s --family f]
ledger quarantine [list]
```

ledger-mcp read tools: `channel_sales_report`, `channel_recon`.
Every import takes optional `--from/--to` and `--fallback-class`. Exit status
is non-zero if anything was quarantined or rejected.

## Rules that are enforced, not documented

- **Idempotency**: `channel_postings` is keyed `(company_id, external_id)`
  (`shopify:<payout>`, `amazon:<settlement>`, `amazon:payout:<id>`). A second
  import is a no-op; the same id with different amounts is `Changed`, nothing
  is replaced, and a quarantine row records the difference.
- **Clearing nets to the payout**: each posting is checked before it is
  written. A mismatch is quarantined (`channel_quarantine`), never plugged.
- **Facilitator tax**: Amazon tax collected and withheld must net to zero per
  settlement (`TaxNotNetted` otherwise). Tax never reaches 2200.
- **Mirrors**: Shopify orders with gateway `amazon` or `ebay` are excluded.
- **Uncaptured** Shopify orders (voided, pending) are not facts.
- **Unmapped SKUs** map to Custom / Other, flagged, listed by `sku-map --unmapped`.
  The mapper is rule based; `sku-map set` overrides.
- Money is minor units throughout. Amazon V2 UTC timestamps fold to Pacific,
  Shopify UTC to Eastern, so V2 and unified agree on a settlement's date.

## Reading the clearing residual

Month-end clearing is zero for Shopify once every payout has landed. For
Amazon, a settlement is paid by a transfer filed under the *next* settlement,
so clearing legitimately holds settlements not yet paid and any pre-window
carry when the import starts mid-history. `channel-recon` shows the balance;
subtract the carry and list the open settlements before calling it a residual.

## Walmart and Etsy (real formats, verified 2026-09-30)

- **Walmart**: Seller Center > Reports > Payments > Payments Reconciliation
  (download is a zip holding one CSV). Period Start/End columns come back
  blank, so periods are derived from the statement cycle (14 days, ending
  Saturdays, anchor 2026-09-19, payout the Tuesday 3 days after). That grid is
  an assumption to confirm against the statement pages. Release Reserve rows go
  to 6620, flagged; Product tax and its withheld twin must net to zero.
- **Etsy**: Finances > Monthly statements > Download CSV (per month; the
  Download Data page's Orders / Deposits CSVs arrive by email and were not
  available). One posting per Deposit row; a deposit must equal the net since
  the previous one, so import every month in one run or the first deposit of a
  gap will be quarantined as opening carry.
